Upgrade the current Final QC App into a shared employee application.

Do not redesign the app. Preserve the current interface, navigation, inspection questions, workflow, PWA behavior, and existing functionality.

AUTHENTICATION

1. Add Clerk authentication using Replit's managed Clerk integration.
2. Require every user to sign in before accessing any part of the app.
3. Only allow verified email addresses ending exactly in:

   @truckranch.com

4. Block Gmail, Outlook, personal emails, and every other email domain.
5. Require email verification before access is granted.
6. Enforce the domain restriction on the server, not only in the frontend.
7. Do not allow users to enter an employee name manually as their identity.
8. Use the authenticated Clerk user ID as the permanent user identifier.
9. Save the employee's verified email address and display name in the app.
10. Add a sign-out button.
11. Provide a clear unauthorized message if someone attempts to use a non-truckranch.com email.

SHARED DATABASE

1. Add Replit's managed PostgreSQL database.
2. Move all inspection data out of localStorage and into the database.
3. All authenticated @truckranch.com users must be able to view all inspections.
4. Inspections must be shared across all phones, tablets, computers, and browsers.
5. Do not use localStorage for inspections, numbering, employee identity, or permanent company records.
6. localStorage may only be used for harmless temporary UI preferences.

INSPECTION ATTRIBUTION

For every inspection, permanently store:

- Unique inspection ID
- Final QC number
- Employee's Clerk user ID
- Employee's verified @truckranch.com email
- Employee display name
- Date and time created
- Date and time last modified
- User ID, email, and display name of the person who last modified it
- Inspection status
- All inspection answers, notes, results, and related data

Display on each inspection:

- Inspected by: employee name
- Employee email
- Inspection date and time
- Last modified by
- Last modified date and time

NUMBERING AND AUDIT HISTORY

1. Generate Final QC numbers in the database.
2. Make the number unique so two employees cannot receive the same number.
3. Use a database transaction or equivalent safe method when generating numbers.
4. Add an inspection activity-history table.
5. Record creation, edits, status changes, completion, reopening, and deletion attempts.
6. Do not allow audit records to be edited or deleted through the normal app interface.

   - View all inspections
